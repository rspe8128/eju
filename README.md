# EJU Study

일본유학시험(EJU) 준비용 개인 학습 웹앱입니다.
학습 진행도는 브라우저 localStorage에 자동 저장됩니다.

## 라이브

https://eju-nu.vercel.app

## 실행

```bash
npm install
cp .env.example .env.local   # DeepL 키 입력
npm run dev
```

## 환경 변수

| 이름 | 용도 |
|---|---|
| `DEEPL_API_KEY` | 모의고사 지문·발문·선택지의 한국어 번역. 무료 플랜 키는 `:fx`로 끝나며 월 50만 자까지 무료. |

`.env.local`은 git에 올라가지 않는다. Vercel 배포 시 Project → Settings → Environment
Variables에 같은 이름으로 등록해야 번역이 동작한다.

## 모의고사 (`/mock`)

한 문제씩 넘겨 가며 풀고, 제출하면 바로 채점·해설이 나온다.

- 회차 선택 → 세션(기술 / 독해 / 청독해 / 청해) 선택 → 문항별 풀이
- **번역 토글** — 지문·발문·선택지 각각 버튼을 눌렀을 때만 한국어가 나온다.
  실전에는 번역이 없으므로 기본값은 항상 숨김이다.
- 한 번 번역한 문장은 localStorage에 저장해 두고 다시 쓴다 (DeepL 무료 한도 절약).
- 채점 결과는 출제 영역별 정답률로 쪼개져 `/stats` 약점 분석에 그대로 쌓인다.
- 풀다 만 세션은 자동 저장되어 이어서 풀 수 있다.
- 단축키: `←` `→` 문항 이동, 숫자 키 `1`~`4` 답 선택

### 수록 문항

| 회차 | 난이도 | 독해 | 기술 | 청독해·청해 |
|---|---|---|---|---|
| 제1회 | 표준 | 25문항 | 2주제 | 준비 중 |
| 제2회 | 실전 | 25문항 | 2주제 | 준비 중 |
| 제3회 | 표준 | 25문항 | 2주제 | 준비 중 |
| 제4회 | 실전 | 25문항 | 2주제 | 준비 중 |

독해는 실전과 같은 구성이다 — 단문 12(1지문 1문항) → 중문 4(1지문 2문항) → 실용문·도표 5.
문항마다 출제 영역 태그와 한국어 해설(오답 이유 포함)이 붙어 있다.

기술(記述)은 자동 채점을 하지 않고 체크리스트로 자가 채점한다. 나중에 AI 채점을 붙일 때는
`writingPrompts[].checklistKo`를 그대로 채점 기준으로 넘기면 된다.

청독해·청해는 섹션만 만들어 두고 문항은 비워 뒀다. `questions`가 비면 목록에서 "준비 중"으로
잠기므로, 문항을 채우기만 하면 다른 코드는 손대지 않아도 된다.

### 왜 JASSO 기출이 아니라 자체 문항인가

기출 PDF에서는 문제를 추출할 수 없다. 이유가 셋 겹친다.

1. **일본어 과목 공개본은 독해 지문이 통째로 삭제돼 있다.** PDF 텍스트 레이어에 남아 있는
   문구가 이것뿐이다 →
   「試験問題としては成立していますが、著作権上の都合により本問題のウェブ掲載はいたしません。」
   (지문 원저자가 웹 게재를 허락하지 않았다.)
2. **수학·종합과목·이과 PDF는 텍스트 레이어가 없는 스캔 이미지**라 기계 추출 자체가 불가능하다.
3. **JASSO 고지상 기출의 번안(=번역)·공중송신은 금지**다. 설령 추출되더라도 한국어 번역을
   붙여 웹에 올리는 형태는 만들 수 없다.

그래서 출제 형식·난이도·문항 수·오답 설계를 EJU에 맞춘 **자체 제작 문항**으로 만들었다.
저작권이 깨끗하므로 지문을 화면에 띄우고 번역까지 붙일 수 있다.
(JASSO PDF를 띄워 놓고 마크시트만 채우던 예전 `/exam` 화면은 위 이유로 걷어냈다.)

### 과목·회차 추가하기

`MockPaper` 스키마는 과목 중립적이다. 수학·종합과목·이과를 넣으려면

1. `src/lib/mock/papers/<이름>/` 아래에 `MockPaper` 객체를 만들고
2. `src/lib/mock/registry.ts`의 `MOCK_PAPERS` 배열에 넣는다.

화면·채점·번역·약점분석은 전부 이 배열만 보고 동작하므로 UI는 손대지 않아도 된다.
문항의 `topicId`는 `src/lib/examTopics.ts`에 정의된 과목별 단원 id를 쓴다.

### 문항 품질 검증

문항을 추가한 뒤에는 검증 스크립트를 돌린다.

```bash
npm run check:mock
```

확인 항목: 정답이 선택지 안에 있는지, id·문항 번호 중복, 없는 지문 참조, 알 수 없는 topicId,
해설 누락, 지문 길이, 선택지 본문 중복, 회차 간 지문 중복, **정답 분포 편중(한쪽 45% 초과)**,
같은 답 4연속. 정답이 특정 번호로 몰리면 실전과 감각이 달라지므로 반드시 통과시킬 것.

## 단어장 보관함 (`/study/library`)

JLPT N3·N2·N1과 EJU 과목 용어를 합쳐 **8,259단어**가 들어 있다. 다만 처음부터 전부
학습 목록에 넣지는 않는다. 필요한 덱만 골라 담고, 안 쓰면 빼는 방식이다.

이유는 두 가지다.

1. **복습 큐** — 새 카드는 전부 "오늘 복습" 대상이다. 만 장을 한꺼번에 넣으면
   `/study/today`가 무의미해진다. 한 덱을 400단어 안팎으로 끊어 두었으니 한 권씩 끝내자.
2. **저장 공간** — 아래 참고.

덱을 담을 때만 해당 단어 파일을 내려받는다(동적 import). 목록만 볼 때는 개수
(`manifest.ts`)만 읽으므로 수백 KB를 헛되이 받지 않는다.

### 저장 공간

학습 기록은 전부 브라우저 localStorage에 있다. 한도는 Chrome·Firefox 약 10MB,
**Safari 약 5MB**이고, 문자열이 UTF-16이라 **문자 하나가 2바이트**로 계산된다.

카드를 그대로 JSON으로 저장하면 한 장에 259자가 든다. 그런데 그중 실제 내용은
30자뿐이고 나머지는 반복되는 키 이름과 deckId다. 그래서 `src/lib/storage/codec.ts`가
저장 직전에 덱별로 묶고 키 이름을 뺀 배열로 바꾼다.

| | 카드당 | 기본 5,726장 | 전부 담았을 때 13,985장 |
|---|---|---|---|
| 압축 전 | 259자 | 2.83MB | 6.18MB ← Safari 한도 초과 |
| 압축 후 | 105자 | 1.19MB | **2.41MB** (한도의 48%) |

카드 id는 압축해도 그대로 남긴다. 오답노트가 카드 id를 참조하므로 id를 다시 만들면
오답 기록이 끊긴다. 20자를 더 아끼자고 살 위험이 아니다.

`saveData()`는 **예외를 던지지 않는다.** 한도를 넘기면 실패 사유를 문자열로 돌려주고,
보관함 화면의 저장 공간 미터에 경고가 뜬다. 예전에는 여기서 던진 예외가 React 상태
갱신 도중에 터져 화면이 통째로 죽었다.

### 단어 데이터 만들기

원본은 `vocab-staging/*.json`이고, 앱이 쓰는 형태로 바꾸는 것은 생성 스크립트다.

```bash
python scripts/gen-vocab.py
```

- 이미 앱에 있는 단어(N5·N4 덱, 기존 용어 덱 등)와 중복되면 제외한다
- 결과는 `src/lib/data/vocab/*.json` + 타입만 붙인 얇은 `.ts` 래퍼
- 개수는 `manifest.ts`에 따로 뽑아 둔다

**단어를 TS 배열 리터럴로 두지 말 것.** `["단어","읽기","뜻","","romaji"]` 같은 리터럴
수천 개를 `WordEntry` 튜플 타입에 맞춰 검사시키면 tsc가 파일 하나에 45초 이상 걸린다.
JSON으로 두면 `string[][]` 하나로 추론되고 끝나서 3초면 통과한다.
같은 이유로 `vocab-staging/`은 `tsconfig.json`의 `exclude`에 넣어 두었다.
