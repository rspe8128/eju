# EJU Study

일본유학시험(EJU) 준비용 개인 학습 웹앱입니다.
학습 진행도는 브라우저 localStorage에 자동 저장됩니다.

## 라이브

https://eju-nu.vercel.app

## 실행

```bash
npm install
cp .env.example .env.local   # DeepL 키 입력
npm run dev
```

## 환경 변수

| 이름 | 용도 |
|---|---|
| `DEEPL_API_KEY` | 모의고사 지문·발문·선택지의 한국어 번역. 무료 플랜 키는 `:fx`로 끝나며 월 50만 자까지 무료. |
| `OPENROUTER_API_KEY` | 記述(작문) AI 채점. [openrouter.ai/keys](https://openrouter.ai/keys)에서 발급. |
| `OPENROUTER_MODEL` | 선택. 비우면 `anthropic/claude-sonnet-5`. |

**모델 슬러그는 수시로 바뀐다.** OpenRouter가 옛 모델을 조용히 내리기 때문에, 예전에
쓰던 `anthropic/claude-3.5-haiku` 는 지금 404가 난다. 404가 뜨면 `npm run check:ai` 가
현재 쓸 수 있는 후보를 값싼 순으로 뽑아 준다.

채점 1건에 입력 1.2K · 출력 0.8K 토큰쯤 든다.

| 모델 | 입력/출력 (100만 토큰) | 채점 1건 |
|---|---|---|
| `anthropic/claude-sonnet-5` (기본) | $2 / $10 | 약 15원 |
| `google/gemini-3.5-flash` | $1.5 / $9 | 약 13원 |
| `google/gemini-3.1-flash-lite` | $0.25 / $1.5 | 약 2원 |

일본어 첨삭이라 싼 모델은 품질 차이가 눈에 띈다. 기본값을 권한다.

두 키 모두 **서버 라우트에서만** 읽는다. `NEXT_PUBLIC_` 접두사를 붙이면 브라우저 번들에
그대로 박혀서 아무나 쓸 수 있게 되므로 절대 붙이지 말 것.

```bash
npm run check:ai   # OpenRouter 연결·키·모델 슬러그 한 번에 확인
```

`.env.local`은 git에 올라가지 않는다. Vercel 배포 시 Project → Settings → Environment
Variables에 같은 이름으로 등록해야 번역이 동작한다.

## 모의고사 (`/mock`)

한 문제씩 넘겨 가며 풀고, 제출하면 바로 채점·해설이 나온다.

- 회차 선택 → 세션(기술 / 독해 / 청독해 / 청해) 선택 → 문항별 풀이
- **번역 토글** — 지문·발문·선택지 각각 버튼을 눌렀을 때만 한국어가 나온다.
  실전에는 번역이 없으므로 기본값은 항상 숨김이다.
- 한 번 번역한 문장은 localStorage에 저장해 두고 다시 쓴다 (DeepL 무료 한도 절약).
- 채점 결과는 출제 영역별 정답률로 쪼개져 `/stats` 약점 분석에 그대로 쌓인다.
- 풀다 만 세션은 자동 저장되어 이어서 풀 수 있다.
- 단축키: `←` `→` 문항 이동, 숫자 키 `1`~`4` 답 선택

### 수록 문항

| 회차 | 난이도 | 독해 | 기술 | 청독해·청해 |
|---|---|---|---|---|
| 제1회 | 표준 | 25문항 | 2주제 | 준비 중 |
| 제2회 | 실전 | 25문항 | 2주제 | 준비 중 |
| 제3회 | 표준 | 25문항 | 2주제 | 준비 중 |
| 제4회 | 실전 | 25문항 | 2주제 | 준비 중 |

독해는 실전과 같은 구성이다 — 단문 12(1지문 1문항) → 중문 4(1지문 2문항) → 실용문·도표 5.
문항마다 출제 영역 태그와 한국어 해설(오답 이유 포함)이 붙어 있다.

기술(記述)은 자동 채점을 하지 않고 체크리스트로 자가 채점한다. 나중에 AI 채점을 붙일 때는
`writingPrompts[].checklistKo`를 그대로 채점 기준으로 넘기면 된다.

청독해·청해는 섹션만 만들어 두고 문항은 비워 뒀다. `questions`가 비면 목록에서 "준비 중"으로
잠기므로, 문항을 채우기만 하면 다른 코드는 손대지 않아도 된다.

### 왜 JASSO 기출이 아니라 자체 문항인가

기출 PDF에서는 문제를 추출할 수 없다. 이유가 셋 겹친다.

1. **일본어 과목 공개본은 독해 지문이 통째로 삭제돼 있다.** PDF 텍스트 레이어에 남아 있는
   문구가 이것뿐이다 →
   「試験問題としては成立していますが、著作権上の都合により本問題のウェブ掲載はいたしません。」
   (지문 원저자가 웹 게재를 허락하지 않았다.)
2. **수학·종합과목·이과 PDF는 텍스트 레이어가 없는 스캔 이미지**라 기계 추출 자체가 불가능하다.
3. **JASSO 고지상 기출의 번안(=번역)·공중송신은 금지**다. 설령 추출되더라도 한국어 번역을
   붙여 웹에 올리는 형태는 만들 수 없다.

그래서 출제 형식·난이도·문항 수·오답 설계를 EJU에 맞춘 **자체 제작 문항**으로 만들었다.
저작권이 깨끗하므로 지문을 화면에 띄우고 번역까지 붙일 수 있다.
(JASSO PDF를 띄워 놓고 마크시트만 채우던 예전 `/exam` 화면은 위 이유로 걷어냈다.)

### 과목·회차 추가하기

`MockPaper` 스키마는 과목 중립적이다. 수학·종합과목·이과를 넣으려면

1. `src/lib/mock/papers/<이름>/` 아래에 `MockPaper` 객체를 만들고
2. `src/lib/mock/registry.ts`의 `MOCK_PAPERS` 배열에 넣는다.

화면·채점·번역·약점분석은 전부 이 배열만 보고 동작하므로 UI는 손대지 않아도 된다.
문항의 `topicId`는 `src/lib/examTopics.ts`에 정의된 과목별 단원 id를 쓴다.

### 문항 품질 검증

문항을 추가한 뒤에는 검증 스크립트를 돌린다.

```bash
npm run check:mock
```

확인 항목: 정답이 선택지 안에 있는지, id·문항 번호 중복, 없는 지문 참조, 알 수 없는 topicId,
해설 누락, 지문 길이, 선택지 본문 중복, 회차 간 지문 중복, **정답 분포 편중(한쪽 45% 초과)**,
같은 답 4연속. 정답이 특정 번호로 몰리면 실전과 감각이 달라지므로 반드시 통과시킬 것.

### 왜 자동으로 넣지 않는가

예전에는 앱을 처음 켜면 24개 덱 5,726장이 자동으로 들어갔다. 그런데 **새 카드는 전부
"오늘 복습" 대상**이라, 첫 화면부터 복습할 카드가 수천 장 쌓여 있었다. 무엇부터
해야 할지 알 수 없는 화면이었다.

지금은 필요한 것만 담는다. JLPT N3 이상은 400단어 안팎으로 끊어 두었으니 한 권씩
끝내고 다음 권을 담으면 된다. (기존 덱은 id가 바뀌면 복습 진행도가 끊기므로 다시
쪼개지 않고 그대로 두었다.)

**이미 쓰던 사람의 덱은 건드리지 않는다.** id가 같으므로 보관함에 "추가됨"으로
표시되고, 빼고 싶으면 직접 빼면 된다.

덱을 담을 때만 해당 단어 파일을 내려받는다(동적 import). 목록만 볼 때는 개수만
읽으므로 수백 KB를 헛되이 받지 않는다.

### 저장 공간

학습 기록은 전부 브라우저 localStorage에 있다. 한도는 Chrome·Firefox 약 10MB,
**Safari 약 5MB**이고, 문자열이 UTF-16이라 **문자 하나가 2바이트**로 계산된다.

카드를 그대로 JSON으로 저장하면 한 장에 259자가 든다. 그런데 그중 실제 내용은
30자뿐이고 나머지는 반복되는 키 이름과 deckId다. 그래서 `src/lib/storage/codec.ts`가
저장 직전에 덱별로 묶고 키 이름을 뺀 배열로 바꾼다.

| | 카드당 | 45권 전부 담았을 때 (13,985장) |
|---|---|---|
| 압축 전 | 259자 | 6.18MB ← Safari 한도 초과 |
| 압축 후 | 105자 | **2.20MB** (한도의 44%) |

카드 id는 압축해도 그대로 남긴다. 오답노트가 카드 id를 참조하므로 id를 다시 만들면
오답 기록이 끊긴다. 20자를 더 아끼자고 살 위험이 아니다.

`saveData()`는 **예외를 던지지 않는다.** 한도를 넘기면 실패 사유를 문자열로 돌려주고,
보관함 화면의 저장 공간 미터에 경고가 뜬다. 예전에는 여기서 던진 예외가 React 상태
갱신 도중에 터져 화면이 통째로 죽었다.

### 단어 데이터 만들기

원본은 `vocab-staging/*.json`이고, 앱이 쓰는 형태로 바꾸는 것은 생성 스크립트다.

```bash
python scripts/gen-vocab.py
```

- 이미 앱에 있는 단어(N5·N4 덱, 기존 용어 덱 등)와 중복되면 제외한다
- 결과는 `src/lib/data/vocab/*.json` + 타입만 붙인 얇은 `.ts` 래퍼
- 개수는 `manifest.ts`에 따로 뽑아 둔다

**단어를 TS 배열 리터럴로 두지 말 것.** `["단어","읽기","뜻","","romaji"]` 같은 리터럴
수천 개를 `WordEntry` 튜플 타입에 맞춰 검사시키면 tsc가 파일 하나에 45초 이상 걸린다.
JSON으로 두면 `string[][]` 하나로 추론되고 끝나서 3초면 통과한다.
같은 이유로 `vocab-staging/`은 `tsconfig.json`의 `exclude`에 넣어 두었다.

덱을 추가·수정한 뒤에는 검증 스크립트를 돌린다.

```bash
npm run check:vocab
```

확인 항목: 덱 id 중복, 목록에 표시되는 개수와 실제 단어 수의 일치, 덱 간 단어 중복
(뜻까지 같을 때만 — 동음이의어는 정상), 빈 표제어·빈 뜻, **전부 담았을 때의 저장 용량**.

## 記述 작문 (`/writing`)

쓰고 저장하면 끝이 아니라 **두 단계로 피드백**이 온다.

**1. 자동 점검 (즉시·무료)** — `src/lib/writing/analyze.ts`

AI 없이 규칙으로 확실히 잡히는 것만 본다. 타이핑하는 동안 실시간으로 갱신된다.

| 항목 | 판정 |
|---|---|
| 분량 | 400~500자 **(공백 제외)**. 미달·초과는 fail |
| 문체 통일 | `です・ます`체가 섞이면 fail — 문제가 된 부분을 인용해서 보여준다 |
| 회화체 | `でも`→`しかし`, `だから`→`したがって` 처럼 대안까지 제시 |
| 단락 구분 | 한 덩어리면 warn |
| 접속 표현 | `まず`·`一方で`·`しかし` 등 사용 여부 |
| 문장 길이 | 120자 넘는 문장이 있으면 warn |
| `〜と思う` 반복 | 4회 이상이면 warn |

> 글자 수를 `body.length`로 세던 버그가 있었다. 공백·줄바꿈까지 세는 바람에
> "420자 (적정 범위)"라고 떠도 실제로는 미달일 수 있었다.

**2. AI 채점 (OpenRouter)** — `/api/grade-writing`

과제 대응 20점 · 구성 15점 · 언어 15점 = **50점 만점**으로 채점하고, 축별 코멘트와
문장 단위 첨삭(원문 → 수정문 → 이유)을 돌려준다. 채점 기준은
`src/lib/writing/rubric.ts` 한 곳에 모아 두어 규칙 검사와 기준이 어긋나지 않는다.

모델이 축을 빠뜨리거나 만점을 초과해 주는 일이 있어서, 응답을 그대로 믿지 않고
기준표를 축으로 삼아 서버에서 다시 맞춘다.

JASSO는 공식 채점표를 공개하지 않는다. 이 점수는 공개된 채점 관점(과제 대응·구성·언어)을
토대로 만든 **연습용 근사치**이며 실제 점수와 다를 수 있다. 점수보다 첨삭을 보자.

그 밖에 초안이 타이핑할 때마다 자동 저장된다. 예전에는 저장 버튼이 본문을 비워 버려서
30분짜리 글이 새로고침 한 번에 날아갔다.

## 청해 딕테이션 (`/dictation`)

**수록 문장 120개.** 예전에는 콘텐츠가 하나도 없어서, 연습하려면 사용자가 일본어 정답
문장을 직접 타이핑해 등록해야 했다. 일본어를 배우려는 사람이 받아쓰기용 문장을 어디서
구해 오나 — 순환 문제라 화면은 늘 비어 있었다.

| 레벨 | 내용 | 문장 | 평균 길이 |
|---|---|---|---|
| 1 | 일상·캠퍼스 회화 | 40 | 14자 |
| 2 | 안내문·설명 (숫자·조건이 섞임) | 40 | 26자 |
| 3 | 강의·논설 (실전 청해에 가까운 문어체) | 40 | 39자 |

**채점이 글자 단위다** — `src/lib/dictation/score.ts`

예전에는 정답 문자열과 완전히 같은지만 봤다. 한 글자만 틀려도 "오답"이고 어디를
못 들었는지는 알려주지 않았다. 받아쓰기에서 정작 필요한 정보가 그건데도.

지금은 LCS로 두 문장을 맞춰 보고 **못 들은 글자는 빨강, 잘못 쓴 글자는 취소선**으로
칠해 준다. 정확도 %와 놓친 글자 수도 함께 나온다. 구두점·띄어쓰기·전각 숫자는
소리로 구분되지 않으므로 채점에서 뺀다.

실전 모드를 켜면 EJU와 같이 음성이 **1회만** 재생된다. 채점 후에는 몇 번이든 들을 수 있다.

음성은 브라우저 내장 Web Speech API를 쓴다. 실제 시험 음성만큼 자연스럽지는 않다.
기출 음원은 저작권상 쓸 수 없으므로 이게 현실적인 최선이다.
